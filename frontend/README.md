# Frontend VectraPKM

Обязательные правила для разработки и агентов: [AGENTS.md](AGENTS.md).

Vue 3, TypeScript, Quasar CLI (Vite), Vue Router. Требуется Node.js 22.12+ или 24 LTS.

```powershell
cd frontend
npm ci
npm run dev
```

Приложение: http://localhost:9000. Маршруты: `/login`, `/register`, `/` перенаправляет на вход. Неизвестный адрес показывает 404.

```powershell
npm run typecheck
npm run lint:check
npm run build
```

`npm run format` форматирует исходники. Сборка создаётся в `dist/spa/`.
При размещении на сервере настройте fallback на `index.html` для маршрутов Vue Router (history mode).

- `src/layouts/AuthLayout.vue` — общая оболочка.
- `src/pages/AuthPage.vue` — формы входа и регистрации.
- `src/utils/validation.ts` — правила проверки ввода.
- `src/css/app.scss` — подключение тем и базовые стили; оформление компонентов находится в их scoped SCSS.
- `quasar.config.ts` — Quasar CLI и локализация.

Формы пока проверяют ввод локально и показывают уведомление о будущем подключении сервера. API аутентификации в backend ещё не реализован. Запросы не отправляются, пароли не сохраняются. Политика регистрации соответствует backend: 8–128 символов без дополнительных требований к составу пароля.

Светлая и тёмная темы используют Quasar Dark и общие CSS-переменные. По умолчанию тема системная, ручной выбор сохраняется в localStorage (vectra.theme). Временный переключатель — компонент ThemeToggle в шапке AuthLayout; инициализация темы находится в src/boot/theme.ts.

## Стили и темы

Цвета редактируются в `src/css/theme/_light.scss` и `_dark.scss`: каждая тема задаёт полную карту `$tokens`.
Контракт `src/css/theme/_contract.scss` перечисляет допустимые токены и описывает их назначение.
Сборка проверяет обе карты: лишний или пропущенный токен вызывает ошибку Sass.

| Токен              | Назначение                      |
| ------------------ | ------------------------------- |
| `app-background`   | Фон приложения                  |
| `app-surface`      | Карточки и активные вкладки     |
| `app-surface-soft` | Второстепенные подложки         |
| `app-text`         | Основной текст                  |
| `app-muted`        | Второстепенный текст            |
| `app-border`       | Границы                         |
| `app-link`         | Ссылки и фокус                  |
| `app-primary`      | Основное действие и знак бренда |
| `app-on-primary`   | Текст на основном действии      |
| `app-negative`     | Ошибки                          |
| `app-notice`       | Фон сообщения                   |
| `app-card-shadow`  | Тень карточки                   |
| `app-tab-shadow`   | Тень активной вкладки           |

Например, чтобы поменять фон тёмной темы, измените `'app-background': #14161b` в `_dark.scss`.

Стили компонента пишем в его `<style scoped lang="scss">`:

```scss
@use '../css/theme/contract' as theme;

.card {
  background: theme.token('app-surface');
  color: theme.token('app-text');
}
```

`theme.token()` проверяет имя и возвращает CSS-переменную, например `var(--app-surface)`.
Значения меняются при переключении темы без пересоздания компонентов.
Для нового токена сначала добавьте описание в контракт и значения в обе палитры.
Цветовые литералы храним в палитрах; локальные стили используют семантические токены.

`src/css/theme/_index.scss` выводит CSS-переменные и связывает их с `--q-primary`, `--q-negative`, `--q-dark` и `--q-dark-page` Quasar.
`app.scss` содержит только подключение темы, базовую типографику и поведение ссылок.
Отступы, размеры и адаптивные правила принадлежат компонентам; `:deep()` применяем только для внутренних элементов Quasar.
