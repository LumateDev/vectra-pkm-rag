# Соглашение по frontend

Эти правила обязательны для всех изменений frontend. Расширяем соглашение по мере развития проекта.

## Дизайн-система

- Сначала используйте существующие семантические токены из `src/css/theme/_contract.scss` и подходящие компоненты Quasar. Не создавайте параллельную палитру для страницы.
- В SCSS обращайтесь к токенам через `theme.token('app-surface')`: функция проверяет имя при сборке. Пример импорта: `@use '../css/theme/contract' as theme;`.
- Цвета, цвета границ, фон и тени задавайте токенами. Значения палитр находятся только в `_light.scss` и `_dark.scss`. Не прописывайте цветовые литералы в компонентах, inline-стилях или конфигурации Quasar.
- Если подходящего токена нет, согласуйте с пользователем его назначение и имя до добавления. После согласования добавьте описание в контракт и значения в обе темы, обновите таблицу в README.
- Изменения интерфейса проверяйте в светлой и тёмной темах, включая фокус, ошибки и автозаполнение, если они затронуты.

## Типографика

- Размеры текста задавайте в `rem`, включая заголовки, подписи, кнопки и текстовые размеры в props компонентов. Не используйте `px` для `font-size`, в том числе в `clamp()`, inline-стилях и переменных.
- Корневой размер оставляйте относительным (`100%`); не фиксируйте его в пикселях. В дальнейшем настройка размера шрифта должна масштабировать интерфейс через корневой размер.
- Для `line-height` предпочитайте безразмерные значения, для `letter-spacing` — `em` или `rem`. Не используйте фиксированные размеры контейнеров, которые обрезают увеличенный текст.
- Учитывайте собственные стили Quasar: при необходимости задавайте текстовый размер локально через `:deep()`. Не меняйте CSS в `node_modules`.

## Размещение стилей

- Используйте `<style scoped lang="scss">` рядом с разметкой компонента. Размеры, отступы и адаптивность принадлежат этому компоненту.
- Глобальный `src/css/app.scss` содержит только подключение тем и базовые правила приложения. Не добавляйте туда оформление страниц.
- `:deep()` используйте точечно для внутренних элементов Quasar и ограничивайте контейнером компонента.
- Общие оболочки переиспользуйте через layouts. Не копируйте шапку и переключатель темы на новые страницы.

## Проверка изменений

Запускайте проверки по масштабу изменения: форматирование, `npm run typecheck`, `npm run lint:check`, `npm run build`. Для изменений интерфейса проверяйте затронутые страницы в браузере на обычном и узком экране, а для типографики — также при увеличенном корневом размере шрифта.
